<details markdown="1">
<summary>배치 관련 용어</summary>

| 용어 | 설명 |
|---|---|
| 인라인(In-line) | 장비가 트래픽이 지나가는 **경로 위에 직접** 놓이는 방식. 모든 트래픽이 장비를 거쳐 가므로 차단이 가능하다 |
| 아웃오브밴드(Out-of-band) | 원본 트래픽 경로에서 벗어나, 트래픽의 **사본**만 받아 분석하는 방식. 차단은 못 하지만 서비스에 영향을 주지 않는다 |
| SPAN 포트 | 스위치의 특정 포트로 지나가는 트래픽을 복사해 다른 포트로 보내 주는 포트 |
| TAP | 회선 중간에 설치해 트래픽을 물리적으로 복사해 주는 장비. SPAN보다 패킷 손실이 적다 |
| DMZ | 외부에 공개되는 서버(웹, 메일 등)를 내부망과 분리해 두는 중간 구간 |

# <toc>IDS(Intrusion Detection System)</toc>

### <toc2>정의</toc2>

IDS는 네트워크 트래픽이나 시스템 활동을 모니터링하여 악의적인 행위나 정책 위반을 <mark>**탐지하고 알리는** 시스템</mark>이다. 핵심은 "탐지"와 "경보"이며, 직접 트래픽을 막지는 않는다.

### <toc2>구성 요소</toc2>

NIST SP 800-94 기준 IDPS의 구성 요소는 다음과 같다.

| 구성 요소 | 역할 |
|---|---|
| 센서(Sensor) / 에이전트(Agent) | 활동을 모니터링하고 분석한다. 네트워크 기반·무선 기술에서는 센서, 호스트 기반 기술에서는 에이전트라고 부른다. |
| 관리 서버(Management Server) | 센서·에이전트가 보낸 정보를 한곳에 모으고 이들을 관리한다. |
| 데이터베이스 서버(Database Server) | 센서, 에이전트, 관리 서버가 기록한 이벤트 정보를 저장한다. |
| 콘솔(Console) | 관리자와 분석가가 사용하는 인터페이스로, 설정·관리나 모니터링·분석에 사용한다. |

### <toc2>동작 과정</toc2>

IDS의 동작은 일반적으로 4단계로 설명한다.

```text
[데이터 수집] → [데이터 가공 및 축약] → [침입 분석 및 탐지] → [보고 및 대응]
```

1. **데이터 수집(Raw Data Collection)**: 시스템 사용 내역이나 통신 기록처럼 분석의 근거가 되는 데이터(감사 데이터)를 수집한다. 호스트 기반에서는 호스트의 사용 내역이 기록된 로그 파일에서, 네트워크 기반에서는 네트워크를 지나는 패킷에서 데이터를 수집한다.
2. **데이터 가공 및 축약(Data Reduction and Filtering)**: 수집한 데이터 중 침입 탐지에 필요한 데이터만 걸러내고, 침입 여부를 판정할 수 있도록 의미 있는 정보로 전환한다.
3. **침입 분석 및 탐지(Intrusion Analysis and Detection)**: 가공된 정보를 분석해 침입 여부를 판정하는 <mark>IDS의 핵심 단계</mark>다. 분석 방식에 따라 오용 탐지와 비정상 행위 탐지로 나뉜다.
4. **보고 및 대응(Reporting and Response)**: 침입으로 판단되면 적절한 대응을 자동으로 수행하거나, 보안 관리자에게 침입 사실을 보고해 관리자가 조치하도록 한다.

# <toc>탐지 방식</toc>

IDS/IPS의 성능은 결국 <mark>"무엇을 공격으로 판단하느냐"</mark>에 달려 있다. 대표적인 탐지 방식은 두 가지다.

### <toc2>1. 시그니처 기반 탐지 (Signature-based / Misuse Detection)</toc2>

> 이미 알려진 공격의 패턴(시그니처)과 트래픽을 비교하는 방식

공격 패턴을 데이터베이스로 만들어 두고, 들어오는 트래픽과 비교한다. 백신의 패턴 매칭과 비슷하다.

- **ex)** 페이로드에 `' OR 1=1 --` 같은 문자열이 포함되어 있으면 SQL Injection으로 판단

**장점**

- 알려진 공격에 대한 탐지 정확도가 높고 오탐이 적다.
- 어떤 룰에 걸렸는지 명확해 분석이 쉽다.

**단점**

- 알려지지 않은 위협이나 기존 공격을 살짝 바꾼 변종은 탐지하기 어렵다.
- 시그니처를 지속적으로 업데이트해야 한다.

### <toc2>2. 이상 탐지 (Anomaly-based / Behavior-based Detection)</toc2>

> 평소의 정상 행위를 기준선으로 삼고, 여기서 크게 벗어나는 행위를 공격으로 판단하는 방식

일정 기간 동안 사용자, 호스트, 네트워크 연결 등의 정상 행위를 학습해 정상 상태의 기준 모델을 만들고, 현재 활동을 이 기준과 비교한다. 정상 행위를 학습할 때는 주로 통계적 기법이나 머신러닝을 사용하고, 평소보다 많은 대역폭을 사용하는 프로세스나 일반적으로 닫혀 있는 포트를 여는 디바이스와 같은 비정상적 편차를 표시한다.

- **ex)** 평소 시간당 100건 수준이던 로그인 시도가 갑자기 10,000건으로 증가, 새벽 시간대에 대량의 외부 전송 발생

**장점**

- 시그니처가 없는 신종 공격이나 제로데이 공격도 탐지할 가능성이 있다.

**단점**

- 정상적인 변화(이벤트로 인한 트래픽 급증 등)도 이상으로 판단하므로 <mark>**오탐이 많다**.</mark>
- 기준선을 학습하는 기간이 필요하고, 학습 기간에 이미 공격이 섞여 있으면 그 공격을 정상으로 학습할 가능성이 있다.
- 계속 갱신되는 프로파일은 공격 강도를 아주 천천히 높이는 방식으로 회피될 수 있다.

### <toc2>3. 탐지 방식 비교</toc2>

| 구분 | 시그니처 기반 | 이상 탐지 |
|---|---|---|---|
| 기준 | 알려진 공격 패턴 | 정상 행위 기준선 |
| 신종 공격 탐지 | 어려움 | 가능 |
| 오탐(False Positive) | 낮음 | 높음 |
| 관리 부담 | 시그니처 업데이트 | 기준선 학습·튜닝 |

실제 제품은 한 가지 방식만 쓰기보다 <mark>여러 방식을 섞은 형태</mark>가 많다.

### <toc2>4. 오탐과 미탐</toc2>

탐지 시스템을 평가할 때는 다음 네 가지 경우를 함께 봐야 한다.

| | 실제 공격 | 실제 정상 |
|---|---|---|
| **공격으로 탐지** | True Positive (정탐) | False Positive (오탐) |
| **정상으로 판단** | False Negative (미탐) | True Negative(정상 판단) |

- **오탐(False Positive)**: 정상 활동을 악성으로 잘못 판단하는 것. IDS에서는 불필요한 경보가, IPS에서는 정상 트래픽 차단이 발생한다.
- **미탐(False Negative)**: 악성 활동을 탐지하지 못하는 것

룰을 엄격하게 할수록 미탐은 줄지만 오탐이 늘고, 느슨하게 할수록 그 반대가 된다. 그래서 <mark>IDS/IPS 운영할 때는 이 균형을 맞추는 작업이 필요하다.</mark>

# <toc2>IDS의 유형</toc2>

### <toc3>1. NIDS (Network-based IDS, 네트워크 침입 탐지 시스템)</toc3>

> 네트워크 구간에 센서를 두고, 그 구간을 지나는 패킷을 분석하는 IDS

센서로 패킷의 네트워크·전송·응용 계층 프로토콜을 분석한다. 센서로 분석 시 SPAN이나 Network TAP을 통해 전달받은 트래픽 복사본을 대상으로 한다.

**장점**

- 하나의 센서로 네트워크 구간 전체를 감시할 수 있다.
- 트래픽 사본을 분석하므로 네트워크 성능에 영향을 주지 않는다.

**단점**

- 암호화된 트래픽(HTTPS, SSH 등)의 내용은 볼 수 없다.
- 호스트 내부에서 일어나는 비정상 행위는 탐지할 수 없다.
- 센서 자체를 노린 DoS 공격, 대량의 트래픽을 보내 센서를 마비시키는 공격, 탐지 회피 기법에 취약하다.
- 대용량 트래픽 환경에서는 패킷을 놓칠 수 있다.

### <toc3>2. HIDS (Host-based IDS, 호스트 침입 탐지 시스템)</toc3>

> 개별 서버나 PC에 에이전트를 설치해 해당 호스트를 감시하는 IDS

호스트의 네트워크 트래픽, 시스템 로그, 실행 중인 프로세스, 파일 접근·변경, 시스템·애플리케이션 설정 변경 등을 감시한다.

**장점**

- 다른 장비가 필요하지 않다.
- 복호화된 이후의 데이터를 분석하므로 암호화 트래픽 문제에서 비교적 자유롭다.
- 공격의 성공 여부를 확인하기 쉽다.

**단점**

- 감시할 호스트마다 설치·관리해야 한다.
- 호스트 자원을 사용하며, 공격자가 호스트를 장악하면 HIDS 자체가 무력화되거나 로그가 조작될 수 있다.
- 일부 검사는 실시간이 아니라 주기적으로 실행되고, 경보도 일정 주기마다 모아서 전송하는 경우가 있어 <mark>탐지가 늦어질 수 있다.</mark>

### <toc3>3. NIDS vs HIDS</toc3>

| 구분 | NIDS | HIDS |
|---|---|---|
| 설치 위치 | 네트워크 구간 | 개별 호스트 |
| 분석 대상 | 네트워크 패킷 | 로그, 파일, 프로세스, 시스템 콜 |
| 감시 범위 | 넓음 (구간 전체) | 좁음 (설치된 호스트) |
| 암호화 트래픽 | 내용 분석 어려움 | 복호화 이후 분석 가능 |
| 내부 행위 탐지 | 어려움 | 가능 |
| 관리 부담 | 상대적으로 적음 | 호스트 수에 비례 |

두 방식을 같이 사용함으로써 서로의 장단점을 보완할 수 있다.

### <toc3>4. 그 외의 유형</toc3>
- WIDS(Wireless IDS): 무선랜 프로토콜 자체를 감시하며, 1계층이나 2계층 외의 다른 계층의 트래픽은 분석하지 않는다. 보안 설정이 취약한 기기, 무선 DoS, 중간자 공격(통신 중간에 끼어들어 데이터를 가로채는 공격) 시도 등을 탐지할 수 있다.
- NBA (Network Behavior Analysis): 패킷 내용 대신 트래픽 흐름 정보를 분석해 비정상적인 흐름을 찾는다. 라우터 등이 만드는 NetFlow, sFlow 같은 흐름 데이터를 활용하며, DDoS, 네트워크 스캐닝, 웜, 정책 위반 등에 강하다.

# <toc>IPS(Intrusion Prevention System)</toc>

### <toc2>정의</toc2>

IPS는 IDS의 탐지 기능에 <mark>**차단 기능**을 더한 시스템</mark>이다. 트래픽이 반드시 지나가는 경로 위에 인라인(In-line)으로 위치해, 공격으로 판단된 트래픽을 목적지에 도달하기 전에 막는다.

### <toc2>대응 동작</toc2>

NIST는 IPS의 대응 방식을 세 가지로 나눴다.

| 대응 방식 | 예시 |
|---|---|
| 공격 자체를 중단 | 네트워크 연결이나 세션 종료, 공격에 사용된 계정이나 IP 주소의 접근 차단 |
| 보안 환경 변경 | 방화벽, 라우터, 스위치 설정을 바꿔 공격을 차단, 대상 호스트의 방화벽 설정 변경 |
| 공격 내용 변경 | 악성 부분을 제거하거나 교체(예: 이메일에서 감염된 첨부 파일 제거), 프록시(요청을 대신 받아 전달하는 중계 서버)를 통해 요청을 정규화 |

### <toc2>IPS의 유형</toc2>

위의 IDS 유형과 같은 흐름이므로 간략히 설명하겠다.

| 유형 | 설명 |
|---|---|
| NIPS (Network-based IPS) | 네트워크 경로에 인라인으로 배치되어 구간 트래픽을 검사·차단 |
| HIPS (Host-based IPS) | 호스트에 설치되어 악성 프로세스 실행, 파일·레지스트리 변조 등을 차단 |
| WIPS (Wireless IPS) | 무선 구간을 감시하여 무선 공격 등을 탐지·차단 |
| NBA (Network Behavior Analysis) | 트래픽 흐름(Flow) 통계를 분석하여 DDoS, 웜 확산, 비정상 통신 등을 탐지 |

### <toc2>Fail-Open과 Fail-Closed</toc2>

IPS는 트래픽 경로 위에 있기 때문에 <mark>IPS 장비가 장애를 일으키면 네트워크 전체가 영향을 받는다.</mark> 이때의 동작 방식을 미리 정해 두어야 한다.

- **Fail-Open**: 장애 시 검사 없이 트래픽을 그대로 통과시킨다. 서비스 가용성은 유지되지만 그동안 보안 공백이 생긴다.
- **Fail-Closed**: 장애 시 모든 트래픽을 차단한다. 보안은 유지되지만 서비스가 중단된다.

서비스 특성에 따라 가용성과 보안 중 무엇을 우선할지 선택해야 하며, 일반적으로 바이패스(Bypass) 장치나 이중화 구성으로 이 문제를 완화한다.

# <toc>배치 구조</toc>

```text
[Internet] ── [Router] ── [Firewall] ── [IPS(인라인)] ── [Switch] ── [내부 서버/PC]
                                                            │
                                                            │ (SPAN/TAP)
                                                            │
                                                        [IDS 센서]
                                                            │
                                                     [관리 콘솔/SIEM]
```

- **IPS**는 트래픽이 반드시 거쳐 가는 경로에 **인라인**으로 배치된다. 보통 방화벽 뒤에 두어, 방화벽이 걸러낸 트래픽을 한 번 더 정밀 검사한다.
- **IDS**는 스위치의 미러링 포트나 TAP을 통해 트래픽 **복사본**을 받는 **아웃오브밴드(Out-of-band)** 방식으로 배치된다. 원본 트래픽 흐름에는 관여하지 않는다.

# <toc>IDS와 IPS 한눈에 비교하기</toc>

### <toc2>1. 특징 비교</toc2>

| 구분 | IDS | IPS |
|---|---|---|
| 주 기능 | 탐지 및 경보 | 탐지 및 실시간 차단 |
| 배치 방식 | Out-of-band (미러링/TAP) | In-line (트래픽 경로 위) |
| 대응 방식 | 수동적(Passive) – 관리자가 사후 대응 | 능동적(Active) – 자동 차단 |
| 네트워크 성능 영향 | 거의 없음 | 지연(Latency) 발생 가능 |
| 장애 시 영향 | 탐지만 중단, 서비스 영향 없음 | 서비스 중단 또는 보안 공백(Fail-Open/Closed) |
| 오탐의 영향 | 불필요한 경보 증가 | 정상 서비스 차단 |
| 적합한 상황 | 가시성 확보, 포렌식·사후 분석, 룰 검증 | 알려진 공격의 즉각적인 차단 |

### <toc2>2. 장단점 정리</toc2>

**IDS**

| 장점 | 단점 |
|---|---|
| 트래픽 사본을 분석하므로 네트워크 성능에 영향이 없음 | 탐지만 할 뿐 직접 차단하지 못함 |
| 룰이 잘못되어 오탐이 나도 서비스가 중단되지 않음(Out-of-band) | 대응을 사람이 해야 하므로 실시간 방어가 어렵고 대응이 늦어질 수 있음 |

**IPS**

| 장점 | 단점 |
|---|---|
| 공격을 자동으로 차단 | 오탐 시 정상 트래픽까지 차단 |
| | 장비 장애가 네트워크 장애로 이어질 수 있음 |

### <toc2>3. 공통 한계</toc2>

- **암호화 트래픽**: TLS로 암호화된 트래픽은 페이로드를 볼 수 없다.
- **회피 기법**: 패킷 단편화, 타이밍 조작 등으로 탐지를 우회할 수 있다.
- **운영 부담**: 규칙 업데이트를 지속적으로 해야 한다. <mark>도입만 하고 관리하지 않으면 효과가 크게 떨어진다.</mark>

# <toc>왜 IDS/IPS가 필요한가</toc>

방화벽은 주로 IP 주소, 포트, 프로토콜 같은 **헤더 정보**를 기준으로 트래픽을 허용하거나 차단한다. 예를 들어 "외부에서 80/443 포트로 들어오는 트래픽은 허용"이라는 정책이 있다면, 그 안에 SQL Injection 페이로드가 들어 있더라도 방화벽은 정상 트래픽으로 보고 통과시킨다.

즉, 방화벽은 <mark>**누가, 어디로** 들어오는지는 보지만 **무엇을** 들고 들어오는지는 잘 보지 못한다.</mark> 허용된 경로를 타고 들어오는 공격, 내부에서 발생하는 이상 행위, 이미 침투한 공격자의 활동은 방화벽만으로 확인하기 어렵다. 이 빈틈을 메우기 위해 패킷의 내용(페이로드)과 행위를 분석하는 IDS/IPS가 사용된다.

| 구분 | 방화벽 | IDS | IPS |
|---|---|---|---|
| 주 목적 | 접근 통제 | 침입 탐지 | 침입 탐지 + 차단 |
| 판단 기준 | 주로 IP 주소, 포트 번호 | 헤더 + 페이로드 + 행위 | 헤더 + 페이로드 + 행위 |
| 동작 | 정책에 따라 허용/거부 | 탐지 후 경보 | 탐지 후 실시간 차단 |

# <toc>마치며</toc>

정리하면 IDS는 <mark>트래픽을 지켜보고 알려 주는 시스템</mark>이고, IPS는 <mark>트래픽 경로 위에서 직접 막는 시스템</mark>이다.

1. **IDS**: 트래픽 사본을 받아 분석하는 Out-of-band 방식으로, 공격을 탐지하고 경보를 보낸다. 서비스에 영향이 없는 대신 대응은 사람이 맡는다.
2. **IPS**: 트래픽 경로 위에 인라인으로 배치되어, 탐지한 공격을 실시간으로 차단한다. 대응이 빠른 대신 오탐과 장애가 곧 서비스 영향으로 이어진다.
3. **탐지 방식**: **시그니처 기반**(알려진 공격에 정확, 신종 공격에 취약), **이상 탐지**(신종 공격 탐지 가능, 오탐 많음)으로 나뉘며, 실제로는 이를 섞어 사용한다.
4. **설치 위치**: **네트워크 기반**(NIDS/NIPS)과 **호스트 기반**(HIDS/HIPS)으로 나뉘고, 두 방식은 서로의 약점을 보완한다.

결국 IDS와 IPS의 차이는 탐지 로직보다 **배치 방식과 대응 방식**에 있다. 어느 쪽을 쓰든 <mark>오탐과 미탐의 균형을 맞추는 지속적인 업데이트</mark>가 운영의 핵심이다.
